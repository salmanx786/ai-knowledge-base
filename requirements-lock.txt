# requirements-lock.txt — EXACT reproduction of the working dev environment.

# Generated with:  .venv/bin/python -m pip freeze
#
# Why this file exists (in addition to requirements.txt):
#   requirements.txt is the curated, human-readable spec. It intentionally
#   leaves the ML stack (torch, numpy, transformers, tokenizers, ...) UNPINNED
#   so each platform can resolve appropriate wheels. That flexibility is great
#   for local dev but bad for reproducibility: `pip install -r requirements.txt`
#   on Linux resolves those floating deps to whatever is newest today, which is
#   NOT what runs on the dev machine.
#
#   This lock pins every transitive dependency to the exact version the dev
#   environment runs, so:   development == Docker == production.
#
# How to upgrade (deliberately, everywhere at once):
#   1. Upgrade packages in your dev venv and verify the app still works.
#   2. Regenerate this file:  .venv/bin/python -m pip freeze > requirements-lock.txt
#   3. Rebuild the image. Dev and Docker move together, never apart.
#
# NOTE on torch: the version below (2.5.1) is pinned to match dev. In the
# Dockerfile it is installed from PyTorch's CPU wheel index so the Linux image
# gets the CPU-only build (the equivalent of the CPU wheel dev uses on macOS),
# not the multi-GB CUDA build the default PyPI index would provide. The version
# is identical; only the compiled backend differs, which a CPU host requires.
